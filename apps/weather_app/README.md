# Weather App

Production-grade Flutter weather app (Android 7.0+, iOS 15.0+). Live weather
for any city or your device location, powered by the **Open-Meteo Forecast +
Geocoding APIs** (no API key, no backend). Client-only by design — there is
nothing to self-host and no server that ever sees your data.

- **Docs (read first):** [`docs/`](docs/) — `WAR_ROOM_RECORD.md` is the
  binding build contract (R-1…R-18, B-1…B-7, red-team conditions, Tech Law
  C1–C7); `ARCHITECTURE.md`, `PRD.md`, `design-spec.md`, plus the
  Phase 2/3 review reports.
- **Architecture pointer:** `lib/` follows `ARCHITECTURE.md` §2 —
  `core/` (network, validation, error, units, telemetry),
  `data/` (DTOs, remote/local/device sources, repository impls),
  `domain/` (entities, repository interfaces, usecases — pure Dart),
  `features/` (home, search, hourly, daily, settings, consent, privacy),
  `l10n/` (v1 English-only, arb kept as the translator source).

## Setup

0. **Run the bootstrapper (requires a Flutter SDK):** `tool/bootstrap.sh`.
   It regenerates any missing platform scaffolds (`android/`, `ios/`) via
   `flutter create` — never clobbering existing files (the B-5 backup-rules
   file `android/app/src/main/res/xml/data_extraction_rules.xml` is
   checksummed and restored on any mismatch) — then runs `flutter pub get`
   and prints the manual platform steps below. Idempotent; safe to re-run.
   (No Flutter SDK here? Install per [`.fvmrc`](.fvmrc) — stable 3.44.4 —
   or `fvm use`, then run it.)
1. Apply the **Manual platform steps** below (Android manifest additions +
   iOS Hive backup exclusion) — these cannot be done by `flutter create`.
2. Commit `pubspec.lock` (generated by the bootstrapper on first run).
   CI resolves dependencies with `--enforce-lockfile`.
3. Codegen is not currently used: `riverpod_generator`/`build_runner` were removed
   from dev dependencies — all providers are hand-written plain `Notifier`s per
   R-8/ADR-14 (intl gen-l10n does not use build_runner).

### Manual platform steps (B-5)

`tool/bootstrap.sh` prints these too; they are operator-applied after
`flutter create` because they live outside what the generator owns.

**Android** — `android/app/src/main/AndroidManifest.xml`, on `<application>`:

```xml
<application
    android:usesCleartextTraffic="false"
    android:dataExtractionRules="@xml/data_extraction_rules"
    …>
```

- `android:usesCleartextTraffic="false"` pins cleartext off (it is off by
  default on modern Android; this makes it explicit).
- `android:dataExtractionRules="@xml/data_extraction_rules"` wires the
  backup-exclusion rules that ship at
  `android/app/src/main/res/xml/data_extraction_rules.xml` (Hive boxes +
  SharedPreferences excluded from Auto Backup / device transfer).

**iOS** — exclude the Hive directory from backup. `hive_ce_flutter`'s
`Hive.initFlutter()` (called with no subDir in `lib/main.dart`) stores its
boxes directly in the app's Documents directory (path_provider's
`getApplicationDocumentsDirectory()`). In `ios/Runner/AppDelegate.swift`,
inside `application(_:didFinishLaunchingWithOptions:)` — before
`GeneratedPluginRegistrant.register(with:)`:

```swift
// B-5: keep cached weather (Hive boxes) out of iCloud/iTunes backup.
if var hiveDir = FileManager.default.urls(
    for: .documentDirectory, in: .userDomainMask).first {
    var values = URLResourceValues()
    values.isExcludedFromBackup = true
    try? hiveDir.setResourceValues(values)
}
```

## Build

```bash
tool/build.sh                       # release APK, prod, split per ABI
tool/build.sh --flavor dev           # dev flavor
tool/build.sh --target ipa          # release IPA (macOS only)
SENTRY_DSN='https://<key>@o0.ingest.sentry.io/<id>' tool/build.sh
```

`tool/build.sh` runs analyze → tests → build → the **35 MB per-ABI /
50 MB IPA size gate**. Flavors: `dev` (debug signing, no Sentry DSN) and
`prod`. The Sentry DSN is injected via `--dart-define` — it never appears
in source (EU DSN; DPA confirmation is an owner action, Tech Law C3).

## Privacy & security posture (the short version)

- Coordinates are **2-dp rounded (~1.1 km)**, memory-only, never persisted;
  only the city name is stored (ADR-07). Cache keys are **SHA-256 hashes**,
  payloads are echo-free (B-1).
- Consent flow: in-app consent **before** the OS prompt, 30-day in-app
  decline suppression vs never-reprompt after OS denial, revocation wipes
  coordinates + device cache immediately (one-tap withdrawal).
- Crash reporting (Sentry) is **crash-only** (`tracesSampleRate: 0`, no
  replay, no PII), gated on the first-run disclosure (R-17), with a
  coordinate/query scrubber in `beforeSend` (B-2). Opt-out calls
  `Sentry.close()` **and** purges the envelope cache (B-7).
- Zero secrets in code — structurally: there are no keys to leak.

### Cache HMAC — why we declined it

Red Team AC-5 recommended an HMAC over cache entries (Keystore/Keychain
key) against cache forgery. We implement the finding's **allowed
alternative** — a written rationale instead:

- Threat model: the attacker is someone with **physical access** to an
  unlocked device (or a rooted backup) rewriting the app's private Hive
  files. That attacker can already read everything on the device and can
  MITM the app's traffic (v1 ships without cert pinning, R-6); forged
  cache entries give them nothing they don't already have.
- Impact ceiling: a forged entry changes *displayed weather* for ≤24 h
  (TTL max) and is overwritten by the next network fetch. No auth, no
  payments, no identity flows depend on it.
- Cost: Keystore/Keychain key management + async HMAC on every cache
  read/write, for a v1 client-only app with no server-side trust boundary.

Revisit triggers: a backend/BFF is introduced, cached data drives
non-display decisions, or the threat model otherwise changes.

## Project layout

```
lib/
  main.dart            # init order: prefs -> Hive -> settings -> Sentry -> runApp
  app.dart             # MaterialApp, themes, routes, RootGate
  core/                # config, validation, error, network (+interceptors),
                       # logging, telemetry, units, utils
  data/                # models (DTOs), datasources (remote/local/device),
                       # repositories (impls), di/
  domain/              # entities, repository interfaces (+ abstract
                       # providers, R-9), usecases — pure Dart
  features/            # home, search, hourly, daily, settings,
                       # consent, privacy, common (widgets, tokens)
  l10n/                # app_en.arb (translator source) + hand-written
                       # app_localizations.dart (replaced by gen-l10n later)
test/
  unit/ contract/ widget/ privacy/  + fixtures/
tool/
  build.sh  regen_fixtures.dart  layer_lint/
```
