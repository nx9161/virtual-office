# Keyboard Mapping Spec — 'over' (Run-Over / Game-Over) Overlay State

- **Date:** 2026-10-07
- **Status:** LOCKED (War Room verdict AS-42)
- **Owner:** Game UI/UX Designer seat
- **Applies to:** all arcade-suite v1.0.3+ games using the shared over-state overlay template

## Exact key mapping (over state)

| Key | Action |
|-----|--------|
| `Space` | Advances the over state — triggers `btnRestart` (restart run) |
| `Enter` | Advances the over state — triggers `btnRestart` (restart run) |

**This is the sole keyboard action in the over state.** Advancement routes through the
template's restart button handler only.

## Deliberately dead in this state

Keyboard **mode/difficulty selection is dead by design** in the over state. Difficulty and
mode selection happens **before** the run begins — the over-state overlay offers no
selection keys, no shortcut remapping, and no hidden alternatives.

## Input guard semantics

- When the over-state overlay appears, a **1–2 second input lock** (input guard) begins.
- Any keypress within ~1–2s of overlay show is **swallowed, not queued**: it neither
  advances the state nor sits in a buffer to fire later.
- After the guard window expires, Space/Enter advance via `btnRestart` as above.

> **Ambiguity flag:** the room locked the guard window as "1–2s" / "~1–2s of overlay show".
> The exact duration within that range (1.0s? 2.0s? per-game?) was not fixed. This spec
> records the range as stated; implementations must not silently invent a precise value.
> If a game needs a single concrete number, it must go back to the Game UI/UX Designer
> seat for a lock addendum — no silent tuning.

## Rationale

Prevents the **double-skip regression** seen in tidelantern: a stray keypress (e.g. the
key that ended the run, or a restless tap) must not double-advance past the over screen.
The guard exists because the prior failure mode was a per-game router firing **after**
the template handler on the same event — the guard window at the overlay level makes that
class of double-fire impossible regardless of router ordering.
